## 一、数据源定位结论

APK 内部没有裸露的数据库文件，CPU 资料存放在一个加密容器里，链路如下：

```
assets/assets                       350,456 B，高熵二进制
   │  AES-256/CFB8/NoPadding 解密
   │  key  = hex(MD5(包名)) = 4819cb0ccc29370ab10c29c5ed289b90
   │  iv[i] = key[31-2i]，i=0..15
   ▼
ZIP（单条目）
   │  解压 → filesDir/tmp_uz
   ▼
cpus_db                             6,427,444 B，纯 JSON（非 SQLite）
   │  由 DbMainFunctions 逐字段解析，写入 SQLCipher 本地库 cpus
   ▼
8 张表：{intel,amd} × {products, series, cpu, cpu_data}
```

关键实现位置：

| 环节 | 文件 | 说明 |
|---|---|---|
| 解密 | `smali/com/ijsoft/cpul/d/a.smali`（`AES256Cipher`） | CFB8 流式解密到 `tmp_dc` |
| 密钥派生 | `smali/com/ijsoft/cpul/d/f.smali` → `c(Context)` / `a([B,Context)` | MD5(包名) 转十六进制串作 AES-256 密钥 |
| 解压 | `smali/com/ijsoft/cpul/d/m.smali`（`ZipUtils`） | 取首个 zip 条目写入 `tmp_uz` |
| 建表 | `smali/com/ijsoft/cpul/d/h.smali`（`DbMainSQLiteHelper`） | 8 张表的 CREATE TABLE |
| 导入 | `smali/com/ijsoft/cpul/d/g.smali` | JsonReader 逐字段入库，写 `release_main_db` 版本号 |
| 模型 | `smali/com/ijsoft/cpul/c/j.smali`（`DbCpu`） | 60 个字段的 JSON 映射 |
| 列表/详情 | `res/layout/fragment_*.xml`、`item_list*.xml`、`item_info_*.xml` | 三级导航 + 规格分组 |

分类模型为「产品线 × 平台类型 → 系列 → 型号」：

- `products`：`product_name`（Core i5 / Ryzen 7 / EPYC …）+ `type`（`dk` 桌面 / `mb` 移动 / `sv` 服务器 / `ed` 嵌入式 / `cs` 定制）
- `series`：系列，如 `Core i5 12th Generation`、`Ryzen 7 5000 Series`，`order_family` 控制同级排序
- `cpu`：列表项（名称、核心数、基准/最大频率、上市年月 `YYYYMM`、`order_number`）
- `cpu_data`：60 字段详情（架构、核心代号、工艺、缓存、TDP、插槽、内存、PCIe、核显、指令集、价格…），同一 `id_cpu` 可挂多条变体记录

### 2.3 格式一致性

- 8 张表的**字段名、字段顺序、JSON 键序、字符串/`null` 取值风格**与原库逐字节对齐；原有 3,924 条记录**一条未改**，全部为尾部追加。
- 字段单位沿用原库约定：频率 MHz、缓存 KB、TDP W、`launch` 列表项为 `YYYYMM` 整数、详情页为 `Qn YYYY` 字符串、`launc_price` 为美元。
- `order_number` 在每个系列内从 1 递增，`order_family` 续接原产品线最大序号，保证列表排序不乱。
- L1/L2 缓存按原库「总量」口径填写（如 24 核 i9-14900K：L1 32KB×24=768、L2 32MB），避免与旧条目显示口径冲突。
- 新增 426 条记录全部具备 `core_arch`、`core_name`、`socket`、`mem_type`、`pcie_*`、缓存、TDP 等主规格；`sspec`、`part_number`、`die_size`、`transistor_count`、跑分等无法确证的可选字段留 `null`，不臆造。

### 2.4 防回退处理

`SplashActivity` / `a.a` 中原数据库版本常量 `0xC0764D9`（2018 版）已提升为 `0xC0B0B11`（5 处一致替换）。作用：

1. 老用户升级时会重新导入内置库；
2. 启动时的远端检查（`ijrsoftware.com/json/db_cpus.json`）版本低于内置版本，**不会用 2018 年的旧库覆盖新数据**。

## 六、安装与已知限制

**安装**：由于使用新的签名证书，无法覆盖安装原版。请先卸载旧版，再安装 `CPU-L-2.3.0-cpu2026.apk`。卸载会清除本地收藏与浏览历史。首次启动会比平时慢几秒（需重新解密并导入 7 MB 数据到 SQLCipher 库）。

**限制与说明**

1. **2026 年新平台未纳入**：Intel Core Ultra Series 3（Panther Lake）、AMD Zen 6 等在本说明成稿时缺乏可核验的公开规格表，为避免写入臆造数据，本次未收录。数据集止于 2025 年已上市平台。后续可按下方流程增量追加。
2. **原库遗留问题未清理**（保持原样，避免影响既有条目）：少量 `cpu` 记录指向不存在的 `series`（如 `Intel Pentium T9500`）、3 组 AMD 同名记录、`AMD Ryzen Threadripper 1977X*` 无详情行。带 `*` 者原库标记为未发布/传闻型号。
3. **可选字段留空**：`sspec`、`part_number`、`core_stepping`、`die_size`、`transistor_count`、`max_temp`、`vcore`、跑分与部分首发价未填写 `null` 以外内容，详情页对应行会自动隐藏，不影响显示。
4. **远端接口仍在**：应用仍保留 `ijrsoftware.com` 的隐私政策、错误上报、跑分上传入口，官方站点若失效这些入口会报网络错误，与原版行为一致。

## 七、后续增量维护

`work/` 目录保留了完整可复用的工具链：

| 脚本 | 作用 |
|---|---|
| `work/decrypt.py` | 从 `assets/assets` 解出 ZIP/JSON（验证或导出原始库） |
| `work/ds_intel_*.py` / `work/ds_amd_*.py` | 新增型号的数据表（每款一行，规格用关键字参数覆盖） |
| `work/build_data.py` | 合并进 8 张表，自动分配 id / order，输出 `cpus_db` |
| `work/pack_data.py` | JSON → ZIP → AES-256-CFB8，生成新的 `assets/assets` |
| `work/patch_ui.py` | 界面尺寸/间距补丁（可重复执行，带命中数断言） |
| `work/validate.py` / `work/check_apk.py` | 数据集与成品 APK 校验 |

追加新 CPU 的最小步骤：在 `ds_*.py` 对应系列里加一行 `C(...)` → 跑 `build_data.py` → `pack_data.py` → 替换 `decoded/assets/assets` → 提升 `apktool.yml` 版本号与 5 处 DB 版本常量 → `apktool b` → `uber-apk-signer` 签名。

签名密钥：`work/cpul.keystore`（alias `cpul`，口令 `cpul2026`）。后续版本请沿用同一密钥，以便覆盖安装。
